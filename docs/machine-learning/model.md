# Model

`js/mahjong-ml-model.js` runs the network in plain JavaScript. `ml/train.py` trains the same network in PyTorch, and a parity check makes sure both give the same outputs.

## The network

```
568 features ─► 256 (ReLU) ─► 128 (ReLU) ─► 28 outputs
```

A fully connected network with about 180,000 weights. The 28 outputs are raw scores (logits) for three predictions:

| Outputs | Prediction | Classes |
| --- | --- | --- |
| 0–5 | How the hand ends for this seat | win by self-draw, win off a discard, deal in, someone else self-draws, someone else wins off a discard, a draw |
| 6–16 | The faan of the win, if this seat wins | 3 to 13 |
| 17–27 | The faan of the hand this seat pays for, if it deals in or someone self-draws | 3 to 13 |

Each group goes through its own softmax, so each is a probability distribution.

## Expected points

The predictions combine into one number, the points the position is worth on average, on the full-spicy payout table. A hand of *f* faan is worth 8 × 2^(*f* − 3) points (8 points at 3 faan, 8,192 at the 13-faan limit), and a self-draw is paid by all three other seats:

```
win points  = Σ P(win faan f)  × points(f)
pay points  = Σ P(pay faan f)  × points(f)
expected    = P(self-draw) × 3 × win points
            + P(win off a discard) × win points
            − (P(deal in) + P(someone else self-draws)) × pay points
```

A draw scores nothing. When someone else wins off another player's discard, this seat pays nothing. `model.ev(x)` returns:

| Field | Meaning |
| --- | --- |
| `ev` | Expected points |
| `pWin`, `pDealIn`, `pOtherSelf`, `pDraw` | The outcome probabilities |
| `avgWin` | Points of a win on average, self-draws counted at three payments |
| `winFaan`, `payFaan` | The expected faan of a win and of a hand paid for |
| `gain`, `cost` | The two halves of `ev` |

Because a fast small win and a slow big one land on the same scale, the model doesn't need separate rules for "go fast" or "go big".

## The weights file

Models are JSON (`ml/models/<name>.json`, and `neural-cat/` on [Hugging Face](hugging-face.md)):

```json
{
  "featureVersion": 2,
  "featureSize": 568,
  "dtype": "f16",
  "meta": { "name": "L3", "valLoss": 2.762, "valOutcomeAcc": 0.706, "evPointsCorr": 0.270, "samples": 1692560,
            "data": ["ml/data/league-1", "ml/data/league-2", "ml/data/league-3"], "hidden": [256, 128], "gameVersion": "0.41.0" },
  "layers": [ { "rows": 256, "cols": 568, "w": "<base64>", "b": "<base64>" }, "..." ]
}
```

- `w` is the layer's weights, rows × cols, row-major. `b` is its biases. Both are little-endian float16, in base64. That's about 480 KB for the whole model.
- `meta` records how it was trained: validation loss, how often the most likely outcome was right (`valOutcomeAcc`), how well its expected points track the points the hand really scored (`evPointsCorr`, a correlation), the training data and the game version. Mahjong hands are noisy, so an accuracy around 70% and a correlation around 0.27 are normal: the model is judged by how it plays, not by these numbers.
- `js/mahjong-ml-weights.js` wraps the shipped model as `MahjongMLWeights` for the page. It's generated by `scripts/ml/ship.js` (which `ml/train.py --ship` and the league call).
- **Release names**: each Neural Cat model that ships gets the next release name, NC1, NC2 and so on, and that's the name the game and coach show ("Model NC1." at the start of its description on the Strategies sheet; Lucky Cat's shows as "Model LC21."). The league's name for it (L17) stays in `meta.trainedName`, in `ml/models/` and in the league's results. NC1 is L17. Lucky Cat's releases count on from its league's lc20 the same way: LC21 is the lab's LP2b.

## The API

```js
const M = require('./js/mahjong-ml-model.js');
const model = M.createModel(weights);   // throws if featureVersion or featureSize differ
model.forward(x);                       // the 28 raw outputs
model.predict(x);                       // { outcome: { winSelf, ... }, winFaan: [...], payFaan: [...] }
model.ev(x);                            // expected points and the parts above
M.randomModel(seed);                    // an untrained model, for tests
M.serialize(weights);                   // float32 weights to the JSON format
```

`forward` stores the first layer by input and skips zero features, so a vector of mostly zeros costs little. It reuses two buffers, so it allocates almost nothing per call.

## Parity with PyTorch

After every export, `ml/train.py` writes 16 sample inputs and their PyTorch outputs to `ml/models/<name>.check.json`, and `scripts/ml/parity.js` runs them through the JS model. The largest difference must be under 0.001 (it's usually about 0.000001). Training fails if it isn't.

```bash
node scripts/ml/parity.js ml/models/L3.json ml/models/L3.check.json
```
